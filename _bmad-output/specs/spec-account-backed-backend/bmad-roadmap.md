# BMAD Planning Roadmap

Use BMAD artifacts as the active requirements and delivery plan for this work. This roadmap sequences the next planning steps; it does not authorize implementation before decisions and stories are ready.

1. **Completed: audit source ratings and resolve backend policy decisions.** Source data is 1–5 whole-number ratings (0 means unrated); combine individual source and user values by their counts. The PRD and this spec record the rating visibility, Google email, code resend, session, password, and API compatibility policies. Refresh the local prepared output and reimport before validating source ratings in the graph; the audited local prepared snapshot lacked `ratings.csv`.
2. **Completed: finalize the architecture spine.** It defines target account persistence, credential and session transitions, rating ownership, migration/readiness, and existing API boundaries. Deterministic lint passed, and the material findings from rubric, technology, adversarial, and brownfield reconciliation reviews were resolved.
3. **Completed: create epics and stories.** The final account-backend breakdown contains two epics and eight approved stories, with FR-13 through FR-21 mapped to story-level coverage. Keep source-rating findings and security/privacy constraints in the spec and architecture, not only in dispatch notes.
4. **Next: plan the sprint.** Use `bmad-sprint-planning` to generate tracking for the approved stories. Verification-message issuance limits are fixed at 3 per account and 10 per source IP per rolling hour, counting initial registration and resends together; other endpoint limits remain implementation-time decisions.
5. **Implement and verify.** Use `bmad-build` for each approved story; verify authentication, privacy, error behavior, and existing API behavior.
6. **Begin Android work only after backend completion.** Revisit the product PRD and create a separate BMAD spec and stories for the Android client after this backend scope meets the success signal in `SPEC.md`.
